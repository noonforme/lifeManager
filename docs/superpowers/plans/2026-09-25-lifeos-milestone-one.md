# LifeOS Milestone One Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a safe, runnable Django foundation with the Closing Ledger shell, an empty Daily Register, isolated domain-summary boundaries, authoritative foundation documentation, and no visual browser tests.

**Architecture:** One conventional Django modular monolith lives directly in this repository. `lifeos.core` composes immutable summaries supplied through public functions owned by `lifeos.work`, `lifeos.money`, and `lifeos.habits`; one injected clock date is shared across a dashboard request, and expected failure in one summary is isolated from the others. Development data defaults to the XDG user-data directory, while test settings fail closed unless given an explicitly test-owned temporary database.

**Tech Stack:** Python 3.14, Django 6.1.1, SQLite, uv 0.12+, pytest 9.1.1, pytest-django 4.14.0, Django templates, handwritten CSS, small local vanilla JavaScript, locally bundled Barlow and JetBrains Mono.

**Spec:** `docs/superpowers/specs/2026-09-24-lifeos-restart-design.md`

## Global Constraints

- Bind the development server to `127.0.0.1`; do not enable LAN or remote access.
- Use one `pyproject.toml` and committed `uv.lock`; add no Node runtime or CSS framework.
- Keep `core`, `work`, `money`, and `habits` as ordinary first-party Django apps; add no plugin loader, generic repository, event bus, API layer, HTMX, SPA, service container, or client state store.
- Default personal data to `${XDG_DATA_HOME:-~/.local/share}/lifeos/lifeos.sqlite3`; allow explicit `LIFEOS_DATABASE_PATH` override.
- Test settings must fail closed if their database path is absent, outside the allocated test root, equal to the personal-data path, or an existing file not owned by the test run.
- Obtain the canonical local date exactly once per dashboard request through an injectable clock.
- Server-render complete pages; JavaScript may enhance theme and navigation only and may not hold authoritative state.
- Meet WCAG 2.2 AA requirements described by the spec; retain visible text or structure for every color-coded state.
- Add no screenshots, golden images, pixel comparisons, browser capture rounds, visual-regression service, Playwright, or other browser dependency in milestone one.
- Do not copy source, generated assets, migrations, databases, or personal records from `/home/aUser/improvedCalendar`.
- Do not implement domain models, mutations, salary calculation, or Habit momentum calculation in this milestone.
- Keep the pre-existing untracked root `PRODUCT.md` and `.claude/` content out of commits; the normative product document is `docs/foundation/PRODUCT.md`.

## Review Focus

- `XDG_DATA_HOME`, `HOME`, and `LIFEOS_DATABASE_PATH` values using relative paths, `~`, symlinks, or an existing personal file must resolve safely and predictably; Task 1 pins these cases.
- A test process with missing or forged ownership markers must stop before Django opens any SQLite file; Task 1 pins this fail-closed behavior.
- A dashboard summary raising an expected operational exception must not hide other registers, while an unexpected programming exception must still surface; Task 2 pins both paths.
- User/system theme preference and navigation must remain usable without JavaScript and must not flash an inaccessible state when JavaScript is enabled; Task 4 pins the markup and script contract.
- Readiness must not leak configuration or record content and must return an unsuccessful status when the database is unavailable; Task 3 pins both responses.
